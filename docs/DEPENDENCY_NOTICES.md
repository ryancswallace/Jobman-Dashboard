# Dependency inventory and upstream notices

`make gen-notices` rebuilds the production browser bundle and regenerates
`THIRD_PARTY_INVENTORY.json` and `THIRD_PARTY_NOTICES.md`. Run `npm ci --prefix web
--ignore-scripts` first when the web lock changes. Use the pinned Go, Node, and npm
versions. Commit both outputs with dependency or bundle changes.

`make notices-check` rebuilds and compares the generated bytes. The normal CI
gate, canonical release builder, and snapshot hooks run this check. Canonical
archives record the inventory and notice hashes in `build.json`; native packages
and container contexts preserve those files. Published artifacts and their
original SPDX inventories are never rewritten by this generator.

The inventory records observations, not a license compatibility decision:

- Go entries are the dependency union of `jobman-dashboard` and
  `jobman-log-broker` for Linux amd64 and arm64 with CGO disabled. Each entry
  names its binary/architecture observations and immutable module checksum.
- Browser entries come from the production bundle's rendered modules, extracted
  CSS/assets, and worker bundles. Fully removed JavaScript dependencies and test
  tooling are not treated as bundled application code.
- Vite preload and Rolldown runtime helpers are explicitly mapped to their locked
  provider packages even though their module identifiers are virtual. Unknown
  rendered virtual modules fail the build and need a reviewed provider mapping.
  Rendered helper hashes and source module hashes retain the observed evidence.
- npm entries retain the lock path, version, integrity, resolved archive URL,
  installed package metadata hash, and upstream declared license. The browser
  graph is bound to the exact lock bytes. Root inventory hashes also bind Go and
  web manifests, locks, and toolchain version files.
- Complete upstream license, copyright, notice, patent, and supplemental
  third-party notice text files are retained, including nested files. Recognized
  forms have no extension or a text/document extension; similarly named source
  files such as `notice_response.go` are excluded. A combined
  upstream notice can describe components beyond the code observed in this
  bundle; its text does not add those components to the package inventory.

The JSON schema version is 1. `sourceLocks` maps repository-relative filenames to
SHA-256 values. Each `packages` entry has `ecosystem`, `name`, `version`, `source`,
`observations`, and `notices`; npm entries also retain `declaredLicense`.
Each notice has its package-relative `path`, exact UTF-8 `text`, and byte `sha256`.
The Markdown file is rendered from the same data with presentation whitespace
normalized; original notice text and byte hashes remain in the JSON. Neither file replaces the
publisher's authenticated SPDX, grants deployment acceptance, or changes the
project's license.
