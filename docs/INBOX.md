# Authorized notification history

The inbox stores one record per Dashboard account and original source event, with the original Control recorded time, optional observed completion time, immutable rule matching context, insertion/expiry/read times, and device handoff counts. History expires 30 days after insertion. Disabling, renaming or deleting a rule does not rewrite accepted historical context. Unread counts include only nonexpired items in currently verified namespace scopes.

`GET /api/v1/inbox` accepts `scope` as the same JSON deployment/namespace tuple array used by monitoring queries, `unread=true|false`, `limit` (default 20, maximum 50), and an opaque continuation. Absent scope selects all currently authorized scopes; explicit `[]` selects none. Selections are bounded to 320 namespaces. The response is `InboxItemPage`: `items`, optional `nextCursor`, decimal-string `unreadCount`, `completeness`, `unavailableSources`, `inaccessibleScopes`, and `fetchedAt`. A partial count is a subtotal of verified scopes, not a count or denominator for hidden records. Source failures do not identify inaccessible namespace names or IDs. If no scope can be verified and any source is unavailable, the request fails with `authorization_unavailable` rather than publishing a zero unread count. A successfully verified empty grant set remains a complete empty inbox.

`GET /api/v1/inbox/{inboxId}` resolves an opaque push reference. `PATCH` at the same path accepts exactly `{ "read": true }` or `{ "read": false }`; setting the same state is idempotent. Cookie mutations use the existing CSRF/Origin boundary. Missing, expired, cross-account and currently unauthorized detail references return generic `not_found_or_inaccessible`; an authorization outage returns `authorization_unavailable`.

Every list, detail, read-state update and unread count requires a current authenticated account/alias plus independently verified Control `namespace.read` and `jobs.read`. Source discovery runs before and after job-name enrichment; namespace versions, principal, Control instance and recovery epoch must agree. Final local account and proof-expiry checks run in PostgreSQL after lock waits and after cursor writes. A changed proof invalidates the response; no old item or count is published. SQL transactions have bounded statement/lock timeouts and perform no network I/O. Historical events from a different Control instance are excluded even if IDs collide.

The namespace permission model allows historical facts to remain visible when the current job no longer exists. `jobAvailability` is `available`, `missing` or `unavailable`; `jobName` is fetched only from an authorized current job and is never copied into the persisted inbox. Missing/unavailable detail has no cached name. All client destinations use the item’s source-qualified job reference and perform a fresh authorized read. Original match context includes only rule ID, revision, name, scope kind and outcome predicate; it exposes no other selected namespaces, activation/checkpoint fields or represented principal IDs.

Ordering is insertion time descending then inbox UUID descending. Persistent cursors expire after ten minutes and bind the account, scope selection, unread filter, page size, original browse boundary and current source authority. New entries do not shift an existing browse window. Read-state changes affect later reads; continuations are not immutable content caches. Every replay rechecks current authority. Refresh starts a new window. Cursor quotas and replacement rules are shared with other bounded Dashboard browsing.

`delivery.total` and `delivery.byState` describe durable per-device handoff work. `accepted` means provider acceptance, not phone presentation. No device token, installation secret, provider key, names or log content are included in these counts. A zero-delivery inbox remains usable when devices are muted, ineligible, absent, or an event is too old for push.

The API is connected through `notifications.NewInboxService(store, ruleSources, cursorStore)` and `httpapi.Server.Inbox`. Migration 15 adds owner/source/scope ordering and unread indexes. Targeted checks are `go test -race ./internal/notifications ./internal/httpapi -run '^TestInbox'`, real PostgreSQL `go test -race ./internal/store -run '^TestNotificationInbox'`, `make contracts-check`, and web Inbox tests. These tests establish component and synthetic-database behavior; real AD FS, browser session and physical iPhone/APNs acceptance remain separate gates.
