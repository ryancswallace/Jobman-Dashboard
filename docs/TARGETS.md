# Target monitoring

Dashboard consumes Control's `target-catalogs` feature using `targets.read` delegation over the configured mutually authenticated connection. The source remains authoritative for target state, immutable generation identity, advertised runtime/platform/capability sets, provider metadata and named storage references. Target state does not imply agent connectivity, utilization or capacity. No cloud-provider calls or execution actions are involved.

`GET /api/v1/targets` supports the normal source/namespace scope, a page limit of 1–200 (default 50), and opaque server-held continuations. Results are grouped by deployment ID and namespace ID, then ordered by creation time and target ID descending within each source. Each source has its own inclusive creation cutoff. Mutable configuration is live; this is not a historical snapshot. Exact total strings cover each source's full cutoff catalog. A partial result sums available contributions and identifies unavailable sources rather than counting them as zero.

Aggregate count discovery uses fanout four and discards the one-row probe. Browsing retains at most one source page, avoiding a multi-megabyte buffer per authorized namespace. Control raw rows are bounded to 2 MiB; Dashboard permits up to 3 MiB after source qualification. Outgoing rows normally use at most 2 MiB, with a single-row exception up to 3 MiB for a legal large source row. The unchanged 4 MiB HTTP/native-response and encoded-cursor ceilings, 16 MiB per-account browse budget, 128 MiB global memory-fixture budget and maximum 320 scopes continue to apply. The adapter preserves Control's permitted long provider-region values; both interfaces display an explicitly disclosed 512-character preview of exceptional values.

`GET /api/v1/deployments/{deploymentId}/namespaces/{namespaceId}/targets/{targetId}` returns current configuration and source observation time. The target UUID is always qualified by deployment and namespace. A generation contains up to 200 preview partitions, the full exact `partitionCount` and `partitionsTruncated` disclosure.

`GET /api/v1/deployments/{deploymentId}/namespaces/{namespaceId}/targets/{targetId}/partitions` requires `generationId`; optional limit is 1–200, default 50. Names use the source's byte-order pagination. Dashboard continuations bind the account, scope, target, generation, limit, source instance, recovery epoch and authorization version. Every read verifies current authorization before and after fetching source facts. Control additionally verifies that the requested generation is still current in its authorized database snapshot. A replacement returns `target_changed` (409): both clients discard displayed partition continuation state and reload target detail before restarting. No cursor or stored row establishes permission.

The web interface and native iPhone app provide catalog totals/freshness, source-qualified detail, bounded partition preview and previous/next partition navigation. Empty catalogs, absent resources, unsupported Control contracts and unavailable authority remain distinct from healthy or zero-capacity claims. Debug fixtures are explicitly synthetic and never count as live identity or device acceptance.

Validation covers real local mTLS adapter reads, authority changes and wrong source/generation responses; aggregate pagination/replay, partial sources, actor/query/epoch/grant isolation, large source-row qualification and byte splitting without loss, maximum-scope cursor encoding, strict HTTP selectors, generated contracts, web replacement recovery and iPhone simulator partition navigation. Live Control/AD FS integration remains a separate acceptance gate.
